# T-395: source-bound Kadmos World IR bridge design

Status: design for independent physical preflight; no product implementation is authorized by this document. Owner: physical Codex in native worktree; parent owns Grok review and integration. This is EPIC50 Stage3b, following T-393/T-394 history without renaming those artifacts.

## Intent and selected guarantee

Connect an actual `parseWorldSpec` result to the T-393 Lean reference subset. A successful bridge certificate means that the **entire parsed WorldSpec** has a declared supported profile, its source expression strings were parsed and bound by a Lean checker, and the checked projection is exactly the `World p v f a` consumed by `interpret`. Kernel facts then apply to that World and its supported requests. It does not certify Kadmos YAML parsing, the exporter, generated TS/Python, JS number behavior outside the safe domain, host objects, or physical effects.

Keep `leanprover/lean4:v4.16.0`, Init-only application code, the unchanged standard axiom whitelist `[propext, Quot.sound, Classical.choice]`, and the accepted Core/Distributed split. No mathlib, Veil, new dependency, toolchain/Core/Distributed/legacy edit, solver proof, `native_decide`, `sorry`, `admit`, or custom axiom. Old targets and inventories remain intact. All Lake processes run serially.

## Source facts and choice

Read-only Kadmos commit `fda8c6e42825b35afe5484a4af9d84d9d206ba9a`: `src/types/world.ts` declares `kadmos.world.v0` and string predicates/effects; `src/world_compiler.ts:79` parses YAML into a `WorldSpec`, checks declaration shape, references and identifiers, and returns expression strings; `src/world_expression.ts` tokenizes and evaluates those strings eagerly, with right-associative `=>`; `src/world_compiler.ts` and `src/python_compiler.ts` generate separate target programs. `conformance/fixtures/order_settlement.world.yaml` is real but contains four context variables and the supported arithmetic/state pattern; `tests/test_harness_world_compiler.test.ts` checks its parse order and generated checker behavior. Source context bounds are optional, string context is legal, and the runtime checks finite numbers at operations, not every safe intermediate. T-393 `Harmonia/Applications/Kadmos/World.lean` has `Expr`, `World`, safe integer checks and `initialize`; `Interpreter.lean` has the actual ordered `interpret`; `Balance.lean` has an independent handwritten example, which is **not** the bridge input.

Three viable approaches were assessed:

| Approach | Benefit | Cost / ruling |
| --- | --- | --- |
| Export Lean `World` directly and prove balance again | Smallest code | Rejected: source strings, binding and effect order depend entirely on an untrusted rewrite. |
| Build a general YAML/JS parser in Lean | Stronger source-to-model trust | Rejected for this stage: duplicates Kadmos parsing and broadens the language and proof task. |
| Export parsed fields plus exact source strings; Lean checks a restricted grammar, bindings and complete projection | A modest vertical slice with a meaningful kernel boundary | Chosen. The YAML/JSON-to-Lean serialization remains an explicit external assumption and is checked by reproducible byte comparisons and differential tests. |

## Exact source binding and profile

Add two tracked UTF-8 YAML fixtures: `balance.world.yaml` and `order_phase.world.yaml` under `conformance/kadmos-ir-bridge/`. They are valid existing `kadmos.world.v0` documents, never a new product schema. A separately tracked `profiles.json` names each fixture and the ordered required request fields: balance `['amount']`; order/phase `[]`. The profile is adapter metadata only. Every listed field must occur as `event.<field>` or `request.<field>` in some guard/effect; aliases map to the same `Fin f`. Every occurrence must be listed; all listed fields are required safe integers for every action, even if a particular action does not read them. No inferred input schema or optional/default payload semantics. Empty payload is required for the no-field profile at the formal boundary.

The bridge identifies a source by Kadmos commit, exact YAML bytes SHA-256, normalized parsed-result JSON SHA-256, profile bytes SHA-256, exporter version, and Lean checker version. The physical provenance command reads the pinned Kadmos checkout, compiles the needed TypeScript into private tmp with its installed `tsc`, invokes its actual `parseWorldSpec`, writes deterministic JSON and a Lean data file, and compares both byte-for-byte with tracked artifacts. Hermetic Linux CI uses those tracked parser outputs, verifies their recorded hashes and Lean certificate, and does not assume or fetch a sibling Kadmos repo. The tracked parsed-result JSON is a recorded physical parser result, not a new source of authority. A maintainer with the pinned checkout can rerun the provenance command; this is also required when source artifacts change. Hashes detect drift and bind files; they prove no semantic theorem. Do not run Kadmos build scripts that clean/write its tree or change package-manager state.

The generated Lean data declares a **raw parsed record** with original state/context/invariant/action order, IDs, booleans, bounds/defaults, guard strings or booleans, exact ordered effect strings, directive `null`/string, plus name/version and profile field table. `RawState` has `id`, initial/terminal booleans and inert optional description. `RawVariable` has a type tag, optional integer min/max/default and inert optional unit/description. `RawGuard` distinguishes boolean and string. `RawTransition` retains id/from/to/guard/effects/directive. `RawWorld.extras` retains unknown JSON property paths; nonempty extras reject in Lean. The exporter and artifact checker also reject unknown keys and wrong JSON types before serialization, including wrong-type descriptive fields; no invalid input is normalized into an apparently complete raw record. Lean validates every semantic raw field and confirms the entire proposed `World` equals the checked projection. A checked certificate is a proof term `checkBridge raw proposed = .ok proposed`, not merely `#eval`, SHA, or an exporter assertion. Raw data comes from the external serialization boundary; its equality to actual parser output is an auditable regeneration check, not kernel checked YAML parsing.

List/index contract: `states`, `invariants`, `transitions` retain array order; context retains `Object.keys(spec.context)` insertion order from the actual parser. IDs become `Fin` indices by those orders. No sorting or deduplication. Reject empty/duplicate state, context, transition, invariant and profile-field IDs; unbound phase/action/context/field/effect-target names; empty state/action IDs; and reserved context names `state`, `event`, `request`, `true`, `false`, `null` (including a context key that shadows an environment binding). Reject identifier spellings outside `[A-Za-z_][A-Za-z_0-9]*` for context/field bindings; state/action/invariant IDs remain nonempty source strings but must be unique. Reject unrecognized raw properties that could alter source behavior in a certified fixture, except documented inert `description`/`unit`; unknown schema additions require a new bridge version. Reject missing, string, unsafe, negative-min, inverted, or non-safe max/default bounds; `default` omitted means zero only when zero is in bounds. Require exactly one initial phase, terminal-source exclusion, and state-only invariants. Reject source `event`/`request` paths in invariants, even if the parser accepts them.

Only `guard: boolean` or restricted string expressions are supported. The restricted tokenizer consumes **the entire original string**; accepted nodes are safe decimal nonnegative integer literals, booleans, context identifiers, `event.x`/`request.x`, `state == 'knownPhase'`, parentheses, binary `+ - == < <= > >= && || =>`, and unary `!`. `==` accepts integer operands only, except the exact state/phase form. Precedence and `=>` right associativity match Kadmos; binary operands are evaluated left-to-right and eagerly. `>`/`>=` lower to `not (le l r)` / `not (lt l r)` without swapping operands, retaining error order. Reject unary minus, `!=`, `*`, `/`, decimals, `null`, arbitrary string expressions, nested/property paths other than one field on event/request, unknown escapes, bare event/request, bare state, and any unconsumed token. Do not coerce. Effects must match the source assignment regex target form, use a declared context target, and retain list order and repeated targets. Guard reads source phase/current context; effect RHS reads target phase/current candidate context; invariant reads published phase/context. Exact directive `null` versus string is preserved and proposed directive must match as in T-393.

The source grammar and evaluator are separate from `Expr`: define `SourceExpr` with named reads and source operators; `parseSourceExpr` is a total `Except` parser on `String`; `sourceEval` recursively visits both operands left-to-right and uses unbounded mathematical `Int`, returning only expected-int/expected-bool type errors. It has **no overflow error**. Define `sourceSafe` independently of lowering/Lean `eval`, inductively over that eager visit tree: every reached literal, context/request read and intermediate sum/difference lies within `[-S,S]`. Final safety alone is insufficient. `lowerGuard` and `lowerEffect` bind names to `Expr p v f`; `lowerInvariant` rejects all field reads and binds to `Expr p v 0`. The lowering theorem requires successful lowering, `sourceSafe`, corresponding ordered environments, **and `NamesWF raw fieldNames`**: state IDs, context names and supplied field names are each pairwise distinct. Name-to-`Fin` equality then follows from list no-duplicates, including `state == 'phase'`; without that premise, duplicate phase names make a first-match `stateIs` disagree with source string equality. `projectWorld` checks these tables before lowering and proves `projectWorld_names_wf`; `checkBridge_names_wf` follows from its successful projection. Under those premises `sourceEval = eval`, including type-error order, and Lean cannot overflow. Static sorting ensures a certified guard/invariant is Bool and an effect RHS is Int. This is a theorem about explicit restricted source semantics, not arbitrary JS evaluation. The checker runs `parseSourceExpr` on every original guard, effect RHS and invariant, checks sort and lower results and every projected World field, and requires `initialize proposed = .ok initial`. The source evaluator is defined independently and compared with Kadmos `evaluate` on finite vectors during physical provenance; those results are tracked test evidence, not kernel proof. Defining it as `eval (lowerExpr e)` would be circular. No general claim that the restricted parser matches all of Kadmos's Pratt parser is made.

The certificate is valid for a World, not for every host request. The delivered formal input is T-393 `Request f`, with `payload : Fin f → RawPrimitive`. Its existing `decode` rejects `.missing`, `.null`, `.bool`, `.string`, `.invalidNumber` and unsafe `.int`; the no-field profile has `f = 0`. `.invalidNumber` represents a future adapter's fractional/NaN/infinite token only under an external mapping assumption. An extra runtime property, accessor, proxy or arbitrary host object cannot be represented by this finite formal request; this stage neither implements nor proves a runtime input adapter. Extra **profile JSON** keys fail exporter/artifact validation. SourceSafe is an execution premise for the lowering theorem, not a static certificate gate on every possible future input. The Lean interpreter rejects unsafe reads/intermediates, whereas generated JS may accept a final-safe cancellation. A cross-runtime correspondence claim must enforce or prove safe operations for the relevant execution. Unsupported syntax/types/host behavior are out of subset, not Kadmos semantic bugs.

## Concrete acceptance fixtures and hostile cases

Balance YAML has phase `Ready`, context `balance` integer min 0/max `9007199254740991`/default 100, invariant `balance >= 0`, and `DEBIT Ready→Ready`, guard `event.amount > 0`, null directive, ordered effect `balance = balance - event.amount`. In this design pass the exact YAML in `/private/tmp/t395-balance.world.yaml` was passed to the pinned checkout's installed `parseWorldSpec`; its returned JSON had those exact fields and SHA-256 of YAML bytes `1357baa55f5cc0453a491df264ca75adacad1db580e4bc952dc4adffc900258b`. This is an ephemeral provenance probe, not yet the tracked certification artifact. Once tracked, regenerate and record final hashes. Kernel check must establish the proposed World equals the checked projection; then prove the **source-bound** `DEBIT 30` accepts balance 70 and `DEBIT 130` rejects at bounds, preserving balance 100, plus the 30/20/130 trace ending 50. These statements must use the certified World, not `balanceWorld` from T-393.

The order/phase fixture has phases `A` initial and `B`, integer x default 1 and y default 0, both bounded 0..S; transition `STEP A→B`, true guard, null directive, effects `x = x + 1`, `y = x`; invariant `state == 'B' => y == x` (true at A, true after STEP). The source-bound accepted result is B/(x=2,y=2). If only the candidate World reverses effects, `checkBridge` against the original raw record rejects it. A **consistently changed raw record and candidate** can certify, but its actual `interpret` reaches B/(2,1), fails the invariant, and retains the whole original A/(1,0). The `state == 'B'` effect RHS is a boolean assignment and fails the static Int sort check. Phase semantics is demonstrated by the B invariant and actual `runTransitionEffects_target` API. Changes to IDs, order, phase, directive or expression AST with the original raw record must fail exact candidate comparison; a correctly regenerated new source can certify on its own merits. A whitespace-only expression edit may project to the same World, but changes the source bytes/hash and requires regeneration; `checkBridge` does not reject semantic equivalence merely because text differs.

Failure tests pin missing/duplicate/unbound/reserved names, `request.amount` alias, right-associative implication, eager right-operand visits, string context, optional bounds, event-dependent invariant, unary minus, `!=`, multiply, divide, null, arbitrary string, bad property path, malformed effect and trailing token. The literal `9007199254740992` fails the **static safe-literal check** and cannot certify. By contrast, safe literals `S` and `1` can form a syntactically certified `S+1` expression; for `false && (S+1 < 0)`, `true || (S+1 < 0)`, and `(S+1)-1`, mathematical `sourceEval` has the indicated `.ok` result, `sourceSafe` is false, and lowering followed by Lean `eval` returns `.error .overflow` because evaluation is eager. A guard/effect using such an expression may pass static certification; `interpret` rejects its unsafe execution with `.guardError .overflow` or `.effectError .overflow`. These are required divergence witnesses outside the `lowerExpr_sound` implication, not a generated JS equivalence claim. Some excluded forms are valid Kadmos features, not semantic bugs. No source rewrite silently normalizes them.

## Proof, trust and future handoff

Certified Lean theorems: `lowerExpr_sound` for the restricted `SourceExpr` under explicit `sourceSafe` and environment hypotheses; `checkBridge_exact` entails equality of the checked projection/candidate and initialized state; source-bound balance/hostile outcomes over actual `interpret`. `parseSourceExpr` has closed behavior probes, not a general Kadmos-parser soundness theorem. T-393 rejection frame, accepted Good and directive properties transfer by instantiation. Proof methods: induction on source syntax/effects, `simp` and constructor cases for checker branches, `omega` for safe integer arithmetic, `List.ofFn` observations plus `List.get_ofFn`/`funext`/`Fin.ext` for field equality and whole Result/context equality, and Foundation `Execution.cons` for trace. `>`/`>=` lower with unswapped operands, so the exported balance guard differs from handwritten `balanceWorld`; no proof substitutes that old fixture without a full World equality theorem. Use `decide` only for closed propositions; never `native_decide`. Preserve the existing standard whitelist. The old Kadmos audit imports the three new Bridge product modules and its source manifest expands; its 426/752 counts are baseline only and rise. The new Bridge audit selects its exact manifest plus Bridge-scoped namespace/source declarations, including unused/escaped axioms, without selecting the whole old Application prefix. Both inventories cover their respective certified modules and isolate rejection traps.

External assumptions: correctness of pinned Kadmos parser and TS evaluator as implemented; exporter serialization of the actual returned object; SHA-256/file comparison implementation; JS/Python host representation. Differential tests on the two fixtures and hostile mutations provide finite evidence only. The stage does not prove semantic equivalence of generated TS/Python, current compiler projections, history/savepoints/rollback, physical IO, distributed composition, SMT/TLC, or arbitrary WorldSpec. Next stage can consume the certified `World`, profile, safe-domain relation and source-bound fixture IDs to state target simulation obligations. It must prove or test each generated target separately and record host assumptions; Stage3b does not pregrant that result.

Cost of a wrong ruling: swapped binding/order or weakened unsupported detection can certify the wrong action; treating a digest as semantic proof can bind an incorrect export; claiming JS safe-intermediate equivalence can hide cancellation; conflating source and target phase can authorize an invalid transition. Any such issue is a preflight blocker, not a reason to change the previous assurance or rewrite Kadmos silently.
