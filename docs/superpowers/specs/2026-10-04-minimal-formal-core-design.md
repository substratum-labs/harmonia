# Harmonia 最小形式核心设计草案

状态：待审阅。日期：2026 年 10 月 4 日。

Harmonia 是独立的分布式算法形式化项目。它建立执行语义、证明基础和通向实现的保证链，Kadmos 是首个应用。本设计确定最小核心的边界和验收义务，尚不是实现计划，也不表示下述能力已经完成。

核心决定是：以固定版本的 Lean 4 为基础，由 Harmonia 掌握语义与接口；参考 Veil，选择性移植机制，不将 Veil 作为核心依赖。协议行为只定义一次，参考执行、状态转移关系、验证条件与目标代码从这份定义派生，并分别承担对应证明。

## 项目目标与首期范围

长期支持分布式算法的安全性、明确假设下的活性、故障语义、可复用元定理及实现精化。首期建立可执行动作核心，用 Kadmos 的结算状态机和任务租约验证其价值。

首期包括有限配置中的节点、带类型的请求、局部状态、顺序赋值、拒绝 verdict、单次 savepoint、本地状态机不变量，以及消息、权威存储提交与进程恢复的有限执行模型。

完整 Raft、BFT、FLP、CAP、动态成员变更、自动发现任意归纳不变量、全应用验证和运行时性能承诺不属于首期。TLA+ 可用于具体问题的临时建模，不建设并行的正式编译路线。

当前仓库基线为 `23eaff8`，工具链固定为 Lean 4.16.0。

| 已有部分 | 当前可确认的范围 | 本设计要求的连接 |
| --- | --- | --- |
| `Core/SmallStep.lean` | 接收、超时、丢消息及归纳可达性定义 | 显式成员配置、故障与持久化步骤 |
| `Protocols/TwoPhaseCommit.lean` | 手写协议与初态 agreement 定理 | 完整归纳证明及配置内节点量化 |
| `DSL/Syntax.lean` | 枚举、结构和 SMT datatype 元数据生成 | 包含 guard 与 effects 的带类型动作定义 |
| `SMT/TwoPhaseCommitVC.lean` | 手写两节点查询 | 从动作语义生成，并验证其编码 |
| `Gatekeeper/CExport.lean` | 单独定义的整数状态门禁 | 与源动作的编码及行为对应证明 |

现有 `HappensBefore` 将时间戳大小当成因果先后；新的因果语义应由节点程序序和发送到匹配接收的边建立，再取传递闭包。逻辑时钟的单调性是需要证明的性质，时间戳比较不作为因果关系的定义。

现有三份 2PC 行为尚未连接，宏生成 datatype 不等于生成协议行为。原架构与白皮书保留为历史提案；本文审阅通过后，再同步权威文档和保证主张，不在此次起草中替换它们。

Veil 评估固定在 `21e7c0bb638de6206c6669621619ecd278147827`，使用其 Lean 4.32.0。临时探针确认了顺序 effects、租约 fencing 和重复消息的有限模型检查能力；拒绝与回滚适配层的已检查定理没有 `sorryAx`。对提取执行器建立全输入对应证明尚未完成，出现简化问题；这些结果不认证 Kadmos 现有编译器。

## 结构与依赖边界

以下是逻辑模块边界，最终文件划分由实现计划确定。

| 模块 | 负责内容 | 依赖规则 |
| --- | --- | --- |
| Core | 类型、状态、动作含义、可达性、执行历史与不变量 | 不导入 DSL、求解器、UI 或 Kadmos |
| IR | 可序列化的带类型动作表示及解释器 | 依赖 Core；协议行为的唯一输入 |
| Proof | 解释器、转移关系、验证条件和导出的对应定理 | 不以外部求解结果替代证明 |
| Verification | 验证条件、有限模型探索、求解器适配和反例回放 | 通过固定接口读取 IR |
| Distributed | 节点配置、网络、故障、存储与恢复语义 | 组合 Core 的局部动作 |
| Codegen | 目标编码、解码、运行时表示及代码生成 | 输出必须关联源 IR 与对应证据 |
| Adapters | Kadmos World 解析后的适配与执行契约 | Kadmos 概念不进入 Core |

首期保留仓库已有的 Lean 4.16.0 固定版本，先检查所选机制在该版本上的可实现性。不为了移植 Veil 的新语法直接升级工具链。确需升级时，单独提交兼容性评估和全部证明重检。

## 类型与动作语言

首期 IR 支持 Bool、有限枚举、声明范围内的整数、字符串相等，以及显式的可选值。缺失值、null、布尔值和整数彼此不同。请求解码必须先验证类型，解码失败产生拒绝，不能借类型转换使错误输入合法。

表达式只包含变量读取、常量、同类型比较、布尔逻辑和受限整数运算。支持加减、分支、有限顺序赋值和纯 helper；首期不支持任意 Lean IO、循环、递归、不受限制的函数值、隐式数值转换或浮点运算。

数学整数与 JavaScript number 的行为必须通过数值适配连接。只检查最终值不足以排除中间结果的精度损失。首期认证子集要求证明每个整数运算的输入和中间结果都在安全范围内；无法建立此条件的表达式不得获得跨语言认证。乘除等扩展应另行规定精度、舍入和失败语义。

动作定义包括源阶段、目标阶段、输入类型、guard、effects 和输出 intent。guard 在前状态求值；effects 按声明顺序读取和更新候选上下文。为对应 Kadmos，effects 中的 `state` 读取目标阶段，其余上下文读取当前候选值。该规则由适配配置显式规定，不能依赖各后端的默认行为。

持久的不变量只读取状态。读取当前请求的条件属于请求验证、guard 或单次动作的后置条件；它们不直接作为恢复后仍成立的状态不变量。

## 本地执行与回滚语义

本地解释器是纯函数。一个动作先在私有候选状态上求值，不直接执行写盘或发包。

| 执行结果 | 对 checker 的影响 | 返回信息 |
| --- | --- | --- |
| Rejected | 保持受保护状态、上下文、接受历史和已有 savepoint | 明确原因，不授权 intent |
| Accepted | 发布通过检查的候选状态，保存接受前快照 | 新状态、声明的 intent、动作身份与版本 |

非法动作、guard 不满足、输入错误、求值失败、上下文越界和不变量失败都得到明确拒绝。拒绝诊断单独保存，不能被混入已接受历史。非确定性环境动作中的 Disabled 表示未启用，不替代 API 的拒绝 verdict。

接受只授权 intent，并不声明物理副作用已发生。通用层提供 typed intent；Kadmos 将其适配为 directive。返回的 intent 必须与该动作的声明一致。请求附带 proposed directive 时，Kadmos 适配按现有规则严格检查它与声明的 directive 是否一致，不通过默认转换获得授权。

首期 Kadmos 兼容配置使用单一 outstanding 操作并串行访问 checker。接受后到操作被分类为成功、确认未提交或结果未知之前，不允许另一个接受动作覆盖 savepoint。这是调用契约，不是当前 TypeScript `#busy` 已经提供的异步互斥保证。

合法回滚只恢复该操作的本地快照并消耗 savepoint。拒绝后的回滚不得误撤销另一个已接受动作。没有 savepoint 或操作身份不匹配时返回明确错误；更复杂的多操作事务不在首期。

回滚的物理解释受结果分类约束：确认未提交时可以恢复并按契约重试；结果未知时，即便恢复了本地快照，也必须记录未知状态并进行查询或去重，不允许据此宣称远端被撤销。

## 分布式执行与故障

节点类型是参数，初期实例使用显式有限成员集合。全局不变量、调度和收发步骤都限制在配置成员内，集合中的重复成员必须拒绝。局部处理函数只能读取自己的局部状态、收到的消息和显式证据；全局性质在证明层观察系统，不作为节点运行时可直接读取的 guard。

节点状态分为 durable、volatile 和进程运行状态。Crash 清除协议指定的 volatile 信息并保留 durable 信息；Recover 按明确的恢复函数重建局部状态。存储服务自身丢失提交或发生故障转移属于额外故障模型，不能由进程恢复假设顺带保证。

网络以消息出现次数为语义，使用 List 实现时需定义表示关系并避免将列表顺序当成网络 FIFO 保证。消息逻辑身份与某次传输实例的身份分开；复制可以产生相同逻辑请求的新传输实例。发送、投递、丢弃和复制是分开的全局步骤，协议自行决定去重。

超时是调度输入，不表示另一节点已崩溃。故障配置明确选择允许的环境步骤；无限丢包配置不能作为经典 FLP 的网络假设。

有限探索必须声明节点、数据域、消息数量与历史深度边界。字符串等无限域需要明确的有限实例；达到搜索边界时标记验证范围或未完成，不能静默截断行为后宣称任意执行安全。

有限历史先服务安全性与反例回放。无限执行、公平调度与活性保留扩展边界，不在首期默认施加公平性，也不把未找到安全反例解释为系统一定终止。

## 副作用与提交

一次物理操作最少经历授权、发送请求、权威存储处理、回复与本地对账。中间步骤均允许进程崩溃和网络延迟。

```text
本地授权并生成 intent
          ↓
发出带操作身份与租约证据的请求
          ↓
权威存储检查状态与租约并提交
          ↓
回复到达 或 回复丢失
          ↓
确认结果 或 读取权威状态并对账
```

结果分类为 Committed、NotCommitted、Unknown。超时或连接异常默认只能给出 Unknown，除非执行适配能证明请求未被提交。

首期租约实例假设一个权威存储，其条件检查和结果更新原子执行，已提交结果在本模型覆盖的进程崩溃下保留。检查目标状态、租约身份以及必要的版本；状态已终结或租约失效时，拒绝新提交。重复请求通过稳定操作身份或终态检查消除重复结果写入。

这保证任务结果提交，不保证用户任务代码只运行一次。支付、邮件等外部服务需要自己的去重契约，不从任务状态存储的原子性推出。

Kadmos Redis 实现检查 state 与 token；Harmonia 的 epoch 模型需要定义两者的对应关系，包括 token 不复用、任务实例身份和恢复规则。Redis 脚本原子执行不自动证明存储持久性、异常后整段撤销或发布事件与结果存储一致。首期可以把这些列为边界假设，不能隐藏在“门禁保证”中。

## 执行语义与验证条件的连接

IR 的参考解释器产生明确的结果。转移关系以解释器为定义来源：接受动作对应候选后状态；拒绝是带标签的状态不变步骤。分布式环境步骤通过单独定义扩展该关系，不能在 SMT 中另写一份协议行为。

验证条件首先是 Lean 中的命题。对状态不变量 I，基本义务为：

```text
初始状态合法
合法输入下，I(s) 且动作接受为 s'，推出 I(s')
动作拒绝，推出完整受保护状态保持不变
在 savepoint 调用契约下，回滚恢复先前快照
```

同时验证接受行为与动作语义一致，避免“总是拒绝”满足安全性却失去正确执行能力。协议在不依赖事后不变量拦截时安全，与门禁拒绝危险候选后安全，是两种独立主张。

每项 VC 生成规则都需要 soundness 定理：生成的条件成立，推出源动作的对应性质。语法宏只负责构造 IR，不承担语义正确性的最后裁决。复杂的替换和状态更新优先建立小引理，避免直接展开整个执行器证明每个协议。

SMT 后端只编码声明支持的片段。首期优先有限域与无量词的受限整数条件，不承诺任意参数化协议都落在 EPR。后续 EPR 配置须检查完整 VC 的量词与函数依赖；数学语义的表达能力不等于 SMT 自动化能力。

求解器返回 SAT、UNSAT、Unknown、Timeout 或 Error。只有经 Lean 检查的证明可以标为 Proved。未经检查的 UNSAT 标为 SolverChecked，并记录查询、编码版本与求解器版本；重建失败不得降级后继续标为 Proved。

归纳反例 CTI 与从初态可达的执行轨迹分开。有限模型检查记录具体域、边界、故障配置及背景假设；反例需在参考解释器中回放。除非实现了候选生成与反例反馈循环，不把这些能力命名为 CEGIS。

## 目标代码与可信边界

目标代码使用明确的输入解码与状态编码。声明关系 R 连接源状态与目标状态，再证明接受、拒绝、上下文更新、intent 和回滚的对应。Lean 编译出的程序与 TS、Python、C 的表示转换是不同的保证边界。

首期证据分层记录，不合并成一个“已验证”标签：

| 证据 | 可以主张什么 |
| --- | --- |
| Lean 内核检查的定理 | 在陈述假设下，所指语义的性质成立 |
| 未重建证明的 SMT UNSAT | 指定编码获得求解器支持 |
| 有限域模型检查 | 在声明域与配置内完成探索 |
| Lean 与 TS/Python 差分 | 指定模型和请求序列的实现一致性证据 |
| 代码生成对应定理 | 指定目标与支持范围内的语义保持 |
| 宿主执行契约及验证 | 在接入、并发、存储与恢复假设下传递性质 |

证明记录包含模型、假设、工具链、源版本、支持配置和目标版本。禁止 `sorryAx` 或未声明的协议公理进入正式认证；使用 native 证明机制时明确增加的可信组件。性能数据单独记录，不能替代正确性证据。

## Veil 机制的取舍

| 机制 | 首期决定 | 原因与条件 |
| --- | --- | --- |
| 状态转移、可达性、归纳不变量的组织 | 借鉴思路，基于现有 Core 独立实现 | 语义由 Harmonia 掌握 |
| WP 与动作解释的对应 | 借鉴并评估小范围移植 | 先证明最小语言；不直接引入整套 Loom 单子结构 |
| 符号与具体状态表示的连接 | 保留这一设计原则 | 首期简单表示足够，优化需要表示保持证明 |
| 有限状态探索与带标签反例 | 独立实现最小版本，评估移植局部算法 | 共享参考解释器与回放格式 |
| SMT 编码与证明重建 | 通过可替换后端接入 | 后端内部类型不进入 Core 的公开接口 |
| Veil DSL 与 elaborator 整体 | 不直接移植 | 不引入其默认原子性、Disabled 或其他隐含语义 |
| UI、复杂优化与协议案例全集 | 首期不移植 | 尚不服务最小保证链 |

代码移植前记录来源提交、许可、依赖闭包、语义前提和替换范围。遵守复制代码及其依赖各自的许可要求。上游改进逐项评估，不维持持续合并要求。独立演进不等于保证内容在修改语义后自动继续成立。

## 验收与实施顺序

按以下顺序进入后续实现计划，每一步保留可独立检查的成果。

1. 类型与纯动作解释器：证明确定性、类型保持、顺序赋值、拒绝保持状态及合法回滚。
2. 验证条件生成：证明基本规则与解释器对应；区分原始协议安全与门禁安全。
3. 有限执行与故障：验证成员限制、消息复制、请求延迟、结果未知和恢复；所有反例可回放。
4. Kadmos 适配：明确支持子集，将结算 World 接入参考执行器，再比较现有 TS/Python checker。
5. 租约提交切片：关联存储前置条件、token/epoch 对应与恢复，固定保证范围。
6. 最小导出对应：选择一个目标表示完成编码与动作对应；未证明的目标继续标明测试证据。

首期验收至少覆盖：合法顺序赋值、非法输入、拒绝后 savepoint 保留、回滚后的快照、旧 worker 提交、重复请求、已提交但回复丢失、进程恢复和存储拒绝。

首次对外主张为“定义、证明和验证指定子集下的受门禁约束状态机，以及明确存储假设下的租约结果提交”。升级到“生成实现正确”必须具备相应目标的对应定理，升级到全局协议性质必须同时覆盖网络及故障步骤。

## 设计取舍与后续审阅

选择独立核心增加了维护和证明成本，也让分布式语义能够按 Harmonia 的需求演进。首期限制动作语言和证明范围，用真实 Kadmos 需求检验抽象，不追求复制 Veil 的全部功能。

审阅应重点确认：本地接受与物理提交的区分、单一 outstanding 操作契约、状态不变量与请求约束的边界，以及当前先采用有限实例验证的范围。本文通过审阅后才制定文件级实现计划；此次不改协议代码、编译器或生成门禁。
